Type Definitions

There are 2 major types defined in TestStand, Step Types and Data Types. Step Types determine what shows up in the insertion pallet when editing sequences. Whereas Data Types determine the types of variables you can have.

You can find all types in TestStand under View (Menu)->Types or using the Ctrl+T hotkey.

Why Use Types

Types are used as templates that predefines a specific behaviour, and can simplify development when there are processes that share similarities or need to be repeatedly used in multiple locations.

Rather than copy/pasting expressions or a set of steps, defining a type allows for adding the needed functionality directly from the insertion pallet, and without potential typos or mistakes.

Additionally, when the process needs to be updated, updating the types can easily update all instances of it found everywhere, rather than updating multiple locations manually.

How to Define Types

Step Types

To define a variant of a standard Step Type, copy the existing TestStand type and paste it in the Step Types section of a Sequence File. While types can be defined in the Type Palletes section of TestStand as well, it is better to define it in the Sequence File since it is more transferable.

After making a copy, rename it as desired and open the newly copied type to define specific features it should have.

Most Step Types' attributes can be found in this editor window. However, some are assigned dynamically through TestStand support libraries (Ex. Automatically inserting NI_Flow_End step when adding a while/for/if step). These are found under the Substeps tab of the step editor window.

Data Types

The two major data types to define would be Enumerators and Containers. To add a new data type, simply right click under the Custom Data Types section of a Sequence File and select the data type to be defined.

Enumerators

These types should be defined when you want to restrict specific numeric inputs, define a specific sequence of numeric inputs (Eg. state machine), simplifying numeric inputs by giving them descriptive names, or specifying inputs by using string expressions, or any combination of these reasons.

Containers

These types should be defined when trying to predefine a group of variables, typically used as inputs to functions. Pay attention to the C Struct Passing settings when using structs to pass information to C functions.
