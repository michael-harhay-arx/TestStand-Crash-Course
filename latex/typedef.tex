\chapter{Type Definitions }
\hypertarget{typedef}{}\label{typedef}\index{Type Definitions@{Type Definitions}}
There are 2 major types defined in Test\+Stand, {\bfseries{Step Types}} and {\bfseries{Data Types}}. {\bfseries{Step Types}} determine what shows up in the insertion pallet when editing sequences. Whereas {\bfseries{Data Types}} determine the types of variables you can have.

You can find all types in Test\+Stand under {\bfseries{View (Menu)-\/\texorpdfstring{$>$}{>}Types}} or using the Ctrl+T hotkey.\hypertarget{typedef_typewhy}{}\doxysection{\texorpdfstring{Why Use Types}{Why Use Types}}\label{typedef_typewhy}
Types are used as templates that predefines a specific behaviour, and can simplify development when there are processes that share similarities or need to be repeatedly used in multiple locations.

Rather than copy/\+pasting expressions or a set of steps, defining a type allows for adding the needed functionality directly from the insertion pallet, and without potential typos or mistakes.

Additionally, when the process needs to be updated, updating the types can easily update all instances of it found everywhere, rather than updating multiple locations manually.\hypertarget{typedef_typehow}{}\doxysection{\texorpdfstring{How to Define Types}{How to Define Types}}\label{typedef_typehow}
\hypertarget{typedef_typedefstep}{}\doxysubsection{\texorpdfstring{Step Types}{Step Types}}\label{typedef_typedefstep}
To define a variant of a standard {\bfseries{Step Type}}, copy the existing Test\+Stand type and paste it in the {\bfseries{Step Types}} section of a {\bfseries{Sequence File}}. While types can be defined in the {\bfseries{Type Palletes}} section of Test\+Stand as well, it is better to define it in the {\bfseries{Sequence File}} since it is more transferable.

After making a copy, rename it as desired and open the newly copied type to define specific features it should have.

Most Step Types\textquotesingle{} attributes can be found in this editor window. However, some are assigned dynamically through Test\+Stand support libraries (Ex. Automatically inserting NI\+\_\+\+Flow\+\_\+\+End step when adding a while/\+for/\+if step). These are found under the {\bfseries{Substeps}} tab of the step editor window.\hypertarget{typedef_typedefdata}{}\doxysubsection{\texorpdfstring{Data Types}{Data Types}}\label{typedef_typedefdata}
The two major data types to define would be {\bfseries{Enumerators}} and {\bfseries{Containers}}. To add a new data type, simply right click under the {\bfseries{Custom Data Types}} section of a {\bfseries{Sequence File}} and select the data type to be defined.\hypertarget{typedef_typedefenum}{}\doxysubsubsection{\texorpdfstring{Enumerators}{Enumerators}}\label{typedef_typedefenum}
These types should be defined when you want to restrict specific numeric inputs, define a specific sequence of numeric inputs (Eg. state machine), simplifying numeric inputs by giving them descriptive names, or specifying inputs by using string expressions, or any combination of these reasons.\hypertarget{typedef_typedefcontainer}{}\doxysubsubsection{\texorpdfstring{Containers}{Containers}}\label{typedef_typedefcontainer}
These types should be defined when trying to predefine a group of variables, typically used as inputs to functions. Pay attention to the {\bfseries{C Struct Passing}} settings when using structs to pass information to C functions.
